# HP‑DeskJet2132(PCL3‑GUI)安卓OTG打印完整开发指南

目标：安卓APK通过USB‑OTG直接驱动HP DeskJet2132系列打印机，不依赖系统打印服务；**Windows抓包得到的`reference_2132.pcl3gui`作为官方基准样本做二进制比对调试**。

> 
> 硬件：HP DeskJet 2132；安卓手机支持USB‑OTG；Windows抓包得到`deskjet2132_sample.pcapng`、`reference_2132.pcl3gui`标准PCL3‑GUI流。
> 协议：**PCL3 GUI (Host‑Based，主机渲染协议)**，该打印机没有板载光栅，图片全部由主机渲染位图下发。

## 整体架构选型

1. 协议参考开源仓库：`hplip`（HP官方开源打印栈，Linux实现PCL3‑GUI）
2. 安卓层：Kotlin/Java做OTG USB设备枚举、权限申请；JNI‑NDK调用移植hplip的PCL3‑GUI图像编码逻辑；
3. 调试基准：Windows原厂驱动抓包输出`reference_2132.pcl3gui`作为黄金样本；二进制比对定位编码差异。
4. 输出产物：安卓APK；输入手机Bitmap图片，OTG输出USB bulk‑out字节流给打印机。

> 
> ⚠️关键：HP 2132属于**主机基于(host‑based)打印机**，打印机本身不解析JPG/PNG，主机必须把图片编码为PCL3‑GUI光栅字节流下发。直接下发图片文件只会打印乱码白纸。

# 完整阶段1：Windows侧获取黄金基准样本（你现在已经做到大半）

1. Wireshark USBPcap管理员抓包HP2132完整打印过程，**保存完整原始pcapng：deskjet2132_sample.pcapng**
2. 使用python脚本从pcapng提取纯输出打印流`reference_2132.pcl3gui`

```
import pyshark

cap = pyshark.FileCapture("deskjet2132_sample.pcapng")

with open("reference_2132.pcl3gui", "wb") as f_out:
    for pkt in cap:
        if hasattr(pkt, "usb") and hasattr(pkt.usb, "data_dir"):
            if pkt.usb.data_dir == "OUT" and int(pkt.usb.transfer_type) == 3:
                hex_str = pkt.usb.capdata.replace(":","")
                f_out.write(bytes.fromhex(hex_str))
cap.close()
print("导出完成 reference_2132.pcl3gui")
```

3. **有效性校验（必须）Windows cmd执行**

```
copy /b reference_2132.pcl3gui \\.\USBPRN
```

✅打印机打印测试图片，样本有效；无效则重新抓包。
4. 保存文件：`reference_2132.pcl3gui`，后续二进制比对用Beyond Compare。

# 阶段2：研读开源HPLIP源码，定位PCL3‑GUI实现

hplip开源仓库：[https://github.com/OpenPrinting/hplip](https://github.com/OpenPrinting/hplip)

> 
> HP官方开源驱动，Linux下原生支持DeskJet2130/2132。

## 关键源码路径

1. `hplip/raster/pcl3gui.cpp`：**PCL3‑GUI光栅编码核心**，位图转打印机字节流；
2. `hplip/usb/usb.cpp`：Linux usb bulk‑out通信；
3. 设备ID：DeskJet 2132 `VID=0x03F0 PID=0x9111`。

### 重点阅读

PCL3‑GUI协议包头定义、压缩模式、行编码、页面参数（纸张尺寸、DPI，2132默认300DPI）。

> 
> Windows抓包样本`reference_2132.pcl3gui`可以用来对照hplip输出，看每一段包头、光栅数据是否字节对齐。

> 
> 开发策略：**不要全部移植hplip庞大框架**，只提取：PCL3‑GUI光栅编码模块，剥离Linux‑USB依赖；USB通信交给安卓Android USB Host API。

# 阶段3：安卓工程搭建（Android Studio + NDK）

## 3.1 工程配置

1. 创建Native‑Kotlin项目，启用NDK；`build.gradle`配置cmake。
2. `AndroidManifest.xml`增加OTG权限

```
<uses‑feature android:name="android.hardware.usb.host" />
<uses‑permission android:name="android.permission.USB_PERMISSION"/>
```

3. res/xml/device_filter.xml，声明HP打印机VID/PID

```
<?xml version="1.0" encoding="utf‑8"?>
<resources>
    <usb‑device vid="0x03F0" pid="0x9111"/>
</resources>
```

4. AndroidManifest注册USB广播接收者。

## 3.2 Java/Kotlin上层职责

1. 枚举USB设备，识别VID=0x03F0 PID=0x9111；动态申请USB权限。
2. 打开USB设备，找到BULK‑OUT端点（打印机输出端点）。
3. 加载图片得到`android.graphics.Bitmap`，把Bitmap像素指针传递给JNI。
4. JNI返回编码完成的PCL3‑GUI字节数组；调用`UsbDeviceConnection.bulkTransfer()`下发字节流。

> 
> ⚠️安卓USB Host bulkTransfer单次最大建议 16384字节，大的打印流分片循环发送。

## 3.3 NDK‑C/C++模块（核心移植）

1. 从hplip提取精简模块：`pcl3gui_encoder.cpp/h`

- 输入：RGBA8888位图buffer、纸张尺寸、DPI；
- 输出：完整PCL3‑GUI二进制字节数组（和Windows `reference_2132.pcl3gui`格式完全一致）。

2. 剥离所有Linux libusb系统调用；USB通信完全交给Kotlin层。
3. JNI接口：

```
// JNI：传入bitmap像素，输出pcl3‑gui二进制打印流
jbyteArray Java_com_example_printlab_Pcl3GuiEncoder_encodeBitmap(JNIEnv* env,jobject thiz,jint width,jint height,jbyteArray pixelData);
```

## 3.4 调试闭环：抓包样本做黄金比对

1. **Windows标准：reference_2132.pcl3gui**（Windows原厂驱动输出，同一测试图片）
2. **安卓NDK输出：android_output.bin**（输入完全相同尺寸内容的Bitmap）
3. Beyond Compare二进制对比两个文件

- 包头字段不一致 → 修改pcl3gui编码器页面参数；
- 光栅数据不一致 → 位图色彩空间、压缩算法bug；
- 完全一致：理论上安卓下发就可以直接打印图片。

> 
> 常见坑：Windows驱动BGR像素顺序；安卓Bitmap RGBA顺序，像素通道颠倒会打印色彩错乱。

# 阶段4：真机OTG调试（APK真实硬件验证）

## 4‑1 硬件连接

安卓手机 + OTG转USB线，接HP DeskJet2132，打印机开机。

1. APK弹出USB权限申请，授予权限。
2. 选择一张测试图片，点击打印。
3. APK调用JNI编码，循环bulkTransfer下发字节流。

### 现象判断

1. ✅正常：打印机出纸，图片和Windows打印一模一样。开发完成。
2. ❌白纸：PCL3‑GUI协议头错误；
3. ❌乱码：下发原始图片而不是光栅流；
4. ❌部分图片截断：bulkTransfer分片逻辑错误，发送缓冲区不足。

## 4‑2 安卓侧抓包备选（如果需要定位OTG通信bug）

安卓没有Wireshark USB抓包；两种方案

1. Windows电脑USB‑Hub中间抓包：手机‑USB‑Hub‑Windows电脑（USBPcap抓）‑打印机；抓取安卓下发的流量，对比Windows抓包黄金样本。
2. APK把JNI输出的`android_output.bin`保存到手机存储，导出电脑，和`reference_2132.pcl3gui`二进制比对。

# 阶段5：问题排查清单（高频踩坑）

1. **Host‑Based打印机误区**：2132不支持直接打印jpg/png，必须光栅编码PCL3‑GUI，直接下发图片文件一定乱码白纸。
2. 像素格式：Windows驱动使用BGR；安卓Bitmap RGBA，通道顺序颠倒会颜色错乱。
3. USB Bulk端点：必须使用BULK‑OUT端点，不要用控制端点；安卓bulkTransfer分片，单次不要超过16384字节。
4. PCL3‑GUI参数：纸张尺寸、DPI、压缩模式，必须和Windows抓包`reference_2132.pcl3gui`头部保持一致。
5. 权限：安卓USB必须用户手动授予权限，后台无法静默获取。
6. 不要复用系统PrintManager，本项目是裸USB OTG驱动，绕过系统打印服务。
