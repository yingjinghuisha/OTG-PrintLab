## 一、AndroidManifest.xml 增加分享接收配置

> 
> 必须配置两套intent‑filter：

1. `ACTION_SEND`：对应微信QQ里的**分享按钮**
2. `ACTION_VIEW`：对应微信QQ预览图片右上角「…」→**其他应用打开**（最常用）

```
<activity
    android:name=".MainActivity"
    android:exported="true"
    android:launchMode="singleTask">

    <!-- 原有USB‑Host权限、metadata、device‑filter -->

    <!-- =====接收微信QQ分享图片 ACTION_SEND===== -->
    <intent-filter>
        <action android:name="android.intent.action.SEND" />
        <action android:name="android.intent.action.SEND_MULTIPLE"/>
        <category android:name="android.intent.category.DEFAULT" />
        <data android:mimeType="image/*" />
    </intent-filter>

    <!-- =====接收「其他应用打开」ACTION_VIEW，微信QQ最常用入口===== -->
    <intent-filter>
        <action android:name="android.intent.action.VIEW" />
        <category android:name="android.intent.category.DEFAULT" />
        <data android:mimeType="image/*" />
    </intent-filter>

</activity>
```

> 
> 配置完成后，你的APP会出现在微信、QQ图片的「分享」、「其他应用打开」列表里面。

## 二、MainActivity Kotlin处理分享Intent

> 
> 用户从微信/QQ唤起你的APP，不走本地图库，直接传入`content://`格式Uri，**不能拿文件路径，必须ContentResolver打开流解码Bitmap**。

```
override fun onNewIntent(intent: Intent?) {
    super.onNewIntent(intent)
    handleShareIntent(intent)
}

override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    handleShareIntent(intent)
}

private fun handleShareIntent(intent: Intent?) {
    intent ?: return
    when(intent.action){
        // 1.分享
        Intent.ACTION_SEND ->{
            val uri:Uri? = intent.getParcelableExtra(Intent.EXTRA_STREAM)
            uri?.let{ decodeUriToBitmap(it) }
        }
        // 2.其他应用打开
        Intent.ACTION_VIEW ->{
            val uri = intent.data
            uri?.let{ decodeUriToBitmap(it) }
        }
    }
}

// 通过content://Uri解码Bitmap（微信QQ全部是content协议，没有真实文件路径）
private fun decodeUriToBitmap(uri:Uri){
    val inputStream = contentResolver.openInputStream(uri)
    val bitmap = BitmapFactory.decodeStream(inputStream)
    inputStream?.close()
    // 拿到bitmap，直接送给JNI PCL3‑GUI编码器
    // 更新UI预览图片，启用打印按钮
}
```

> 
> 拿到`Bitmap`之后，复用你现有的整套流程：
> `Bitmap → JNI pcl3gui编码得到二进制数组 → USB‑OTG bulkTransfer分片下发给打印机`。

### ⚠️重要限制

1. **只做图片打印**：HP DeskJet2132是Host‑Based主机渲染打印机，**不能直接打印PDF、Word文档**；微信收到pdf文档，分享过来APP无法处理，需要过滤MIME类型只接收`image/*`。
2. 安卓分区存储：微信QQ传递过来全部是`content://`，拿不到真实本地路径，**只能通过ContentResolver打开流**，不能直接File读取。
3. `launchMode="singleTask"`：防止多次分享打开多个APP实例。

## 四、完整运行链路（微信QQ端完整流程）

1. 硬件：手机Type‑C → **有源供电拓展坞** → 打印机原装USB‑A‑B线 → HP2132开机
2. 微信打开一张图片预览 → 右上角`...` → **其他应用打开** → 选择你的APK
3. APP被唤起，`handleShareIntent`拿到content Uri，解码出Bitmap
4. Bitmap送入JNI，NDK输出完整PCL3‑GUI二进制打印流
5. Kotlin层USB bulkTransfer循环分片下发数据流
6. 打印机输出图片。

## 五、开发调试避坑清单（新增分享相关坑）

1. ❗不要企图直接转发PDF/Word：2132主机‑based打印机，没有文档解析器，只能接收位图；MIME只注册`image/*`。
2. 微信QQ全部是`content://` Uri，**绝对不要尝试转文件路径**，安卓新版本拿不到真实路径，只能openInputStream。
3. 分享唤起APP之后，USB打印机需要提前授予OTG权限；如果此时还没有授予权限，弹窗申请USB权限，用户确认之后再执行打印。
4. 二进制比对调试：分享进来同一张测试图，APP把JNI输出保存`android_output.bin`导出电脑，和Windows抓包`reference_2132.pcl3gui`做Beyond Compare二进制对比。
5. OTG硬件：依旧强烈推荐**带独立电源有源拓展坞**，无源OTG大图片打印极易掉设备。
